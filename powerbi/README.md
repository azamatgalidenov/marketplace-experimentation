# Power BI report: Marketplace Lab

A PBIP project (PBIR report + TMDL semantic model) with four pages:

| Page | Data | Content |
|---|---|---|
| Executive Overview | **Real** Olist | Orders, delivered share, gross order value, AOV, payments; monthly orders, payment mix, status mix, order value trend, computed observations |
| Historical Operations | **Real** Olist | Late-delivery rate by month, low-review rate by delay bucket, review-score distribution, region and category tables |
| SIMULATED A/B Experiment | **SIMULATED** | Scenario selector, assigned users per arm, completion by variant, absolute/relative lift with 95% CI, decision and reasons, all metrics with guardrail status |
| SIMULATED Diagnostics | **SIMULATED** | SRM test, achieved MDE, data-quality checks, DAX-vs-Python lift check, segment lifts (exploratory), daily allocation, variant metrics |

Screenshots of the four pages, taken in Power BI Desktop after a refresh, are in
[screenshots/](screenshots/).

> The SIMULATED pages show a synthetic experiment generated from the assumptions in
> [docs/experiment_plan.md](../docs/experiment_plan.md). They are not business results.
> Olist has no sessions or checkouts, so no page shows a visitor conversion rate. Order
> and payment values are gross customer payments, not platform revenue.

## Build and open

```bash
uv run python -m marketplace_analytics build            # olist marts
uv run python -m marketplace_analytics experiment       # sim tables
uv run python -m marketplace_analytics export-powerbi   # -> powerbi/data/*.parquet + manifest.json
```

1. Open `powerbi/MarketplaceLab.pbip` in Power BI Desktop. If your Desktop version
   asks, enable the Power BI Project (.pbip) preview feature.
2. If the repository is not at `C:\Users\User\python projects\marketplace-experimentation`,
   set the **DataFolder** parameter (Transform data → Edit parameters) to the absolute
   path of `powerbi/data`. Its value lives in
   `MarketplaceLab.SemanticModel/definition/expressions.tmdl`.
3. **Refresh**, then save. `powerbi/data/` is gitignored, so the report shows no data
   until the export has run and the model is refreshed.

To regenerate the report pages after editing the generator:

```bash
uv run python -m marketplace_analytics powerbi-report   # rewrites MarketplaceLab.Report/definition/pages
```

Close the report in Desktop first, or reopen it afterwards. Desktop does not pick up
file changes to an open report.

## How it is built

- **Export (`reporting/powerbi_export.py`).** Each query in `sql/powerbi/` becomes one
  Parquet file. `hist_*` files read only `olist.*` and `sim_*` files read only `sim.*`.
  The export refuses any query that mentions the simulation's true parameters, and it
  writes the current `sim_*` quality-check results to `sim_quality_checks.parquet`.
- **Semantic model (`MarketplaceLab.SemanticModel/`, TMDL).** Import mode with 14 tables.
  - Real-data tables: three fact tables (`Orders`, `Order Items`, `Payments`) share the
    `Date`, `Customer Region` and `Product Category` dimensions (single-direction,
    many-to-one).
  - The `SIM *` tables relate only to `SIM Scenario`, never to real-data tables.
  - The 43 measures have descriptions, display folders and format strings.
  - The report-level filter `Date[In Analysis Window] = true` applies the same analysis
    window as the Python/SQL pipeline. The SIM tables are not related to `Date`, so it
    does not affect them.
- **Report (`MarketplaceLab.Report/`, PBIR).** Pages are generated by
  `reporting/powerbi_report.py` from the design contract in
  [_brief/report-spec.md](../_brief/report-spec.md): a 1920×1080 canvas on a 12×12 grid.
  IDs are hashes of stable names, so regenerating produces identical files. Chart
  titles that state a finding are DAX measures (e.g. `Observations Text`), not typed
  text.

## Validation performed

- **DAX vs pipeline.** DAX queries against the model loaded in Desktop matched the
  Python/SQL values. Real data: orders 99,092; delivered GMV 13,181,027.13; AOV
  159.79; late rate 6.79%; post-delivery low-review gap 9.09 pp, equal to the
  regression AME. SIMULATED data: lift, CI and decision for all five scenarios. The
  `SIM Lift Check` measure shows "DAX matches Python" on the Diagnostics page.
- **Visual check.** All four pages were opened and refreshed in Power BI Desktop and
  screenshotted. The screenshots were reviewed for clipping, labels and correct values.
- **Automated (`tests/test_powerbi.py`, no Desktop needed):**
  - no measure/column name clashes;
  - every visual field exists in the model;
  - relationships point at real columns;
  - the generator is deterministic and the committed PBIR equals its output;
  - SIMULATED pages use only `SIM` tables and carry a banner;
  - the export writes every table with the columns the model maps, and no `true_*`
    columns.
- The report has **not** been published to the Power BI service or Fabric.

## Known issues and gotchas

- **Measure names must not match a column name.** Desktop refuses to load the model
  ("… cannot be created because the same name already exists"). This is why the
  Payments column is `Payment Amount` and the measure is `Payment Value`. A test
  guards against it.
- **KEEPFILTERS on filtered measures.** A measure such as
  `CALCULATE([Orders], NOT ISBLANK('Orders'[Review Score]))` *replaces* a filter on
  `Review Score` coming from a chart axis, so every bar showed 100%. Measures that
  filter a column also used on an axis wrap the condition in `KEEPFILTERS`.
- **Saving in Desktop rewrites the PBIR files** in its own format: newer schema version,
  reordered keys and default flags. Run `powerbi-report` before committing, so the
  committed pages match the generator. `tests/test_powerbi.py` fails otherwise.
- **Desktop reports unsaved changes after every refresh.** Saving does not clear the
  flag. It has no visible effect on the report.
- **"ActivePageName not found".** Desktop showed this message once while opening the
  report. The page files are consistent and the report opens normally. The cause was
  not identified.
